# 本地输入计数拦截修复

日期：2026-11-06。用户要求生成仅由本人手动触发，本轮不运行用户图片。

## 原因和责任范围

用户手动提交的 `023.png` 在 G0 发送前失败。原图 546 × 342，上传字节没有变化；SAM 返回 4 份图片素材和 14 份箭头素材，加上原图与总览共 20 个附件。原传输层计算图片部分的保守上界为 172032，超过配置的 131072，尚未加入提示词就触发本地拦截。没有生成请求、收据或新增费用。

这段限制与固定上游 `21ffc01271904d6c5610f0f96afd84530968f11e` 相同，不是网页漏调用阶段。但原版一致性不等于可用性，先前仅完成移植及离线一致性验证，没有消除这一使用阻塞。

## 修复边界

当前配置标识：`upstream-factual-gpt55-count-v1`。

在原传输函数增加可选 `input_token_counter` 参数，且仅在网页 worker 中安装回调。回调使用 OpenAI Responses 输入计数接口，保留传入的模型、角色、提示词、图像 data URL、顺序、detail 和 reasoning 设置。

- 生成请求正文与原版完全相同，三个阶段仍全部使用 GPT-5.5。
- 输入上限 131072、输出上限 32768、单图预算 USD 5 和原版费用预留逻辑保持原值。
- 不缩图、删素材、拼板、换模型或追加提示词。
- 实际计数超过上限时仍停止；计数不可用时停止并说明当前阶段尚未发送，只有用户可以手动重试。
- 计数结果保存在各阶段 `call/input-count.json`，不记录凭据或新增生成收据。
- 已完成的生成收据继续按原版规则复用，状态不确定的生成请求不会重发。
- 1111 个归档文件逐一核验；补丁清单分为三处 Windows 兼容修改与一处输入计数回调。其余内核文件不变。

官方依据：

- [输入计数指南](https://developers.openai.com/api/docs/guides/token-counting)：包含图片的完整输入可在生成前计数。
- [接口定义](https://developers.openai.com/api/reference/resources/responses/subresources/input_tokens/methods/count)：`POST /v1/responses/input_tokens` 返回 `response.input_tokens` 与 `input_tokens`。
- [图片输入说明](https://developers.openai.com/api/docs/guides/images-vision)：GPT-5.5 图片按 32 × 32 像素块规则计数，非每张小裁剪固定 8192。

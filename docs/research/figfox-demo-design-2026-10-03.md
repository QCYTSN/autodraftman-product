## 从 DrawAI 学什么

[DrawAI](https://drawai.renaissancemind.ai/) 的重要启发是先给访问者可操作的结果，再解释方法和评测。研究了它的完整页面、案例交互、图表与公开源码；完整证据见 [网站学习报告](drawai-study-2026-10-03.md)。

FigFox 页面依照“介绍 → 真实重建与编辑 → 对照 → 方法 → 使用入口”组织。根据用户对首版过于拥挤的反馈，介绍现在独立占据第一屏，画布位于后面的完整案例区。首页不运行生成请求，访问者直接操作预先计算的 SVG 副本。真实重建结果的不完美同样保留，原图始终可查看。

## 页面职责

| 入口 | 主要内容 | 当前状态 |
| --- | --- | --- |
| `/` | 公开演示、案例、方法、Try 入口 | 新设计；本地运行有三个互动案例 |

视觉和访问逻辑上，演示页独立于工作台；当前不需要另建仓库或立即换框架。首页自己的导航是案例、方法、源代码和开始使用，页脚提供指南、定价与隐私入口。

## 技术和模块

继续使用 React、TypeScript 与 Vite，首页实现位于 `frontend/src/features/demo/`：

- `FigFoxDemoPage.tsx`：双语页面、章节与工作台入口，原图滑动对照、方法图弹窗。
- `DemoCanvas.tsx`：原生 SVG DOM 的轻量交互，不引入完整编辑器或图表引擎。支持拖动、文字编辑、方向键微调、恢复、缩放、适应画布、按住查看原图及下载。
- `HeroSvgWord.tsx`、`heroSvgGlyphs.ts`：使用指定 Google Sans Flex 字形的 SVG 路径，解释关系重建、对照检测和局部修复；这是一段方法示意，不是实验结果。
- `cases.ts`：案例名称、尺寸和素材地址。
- `demo.css`：首页范围内的字体、颜色、布局、响应式与动效。
- `useDemoMotion.ts`：按标题与展示块分别观察可见性；以被动滚动监听和浏览器帧更新处理首屏轻微移动，减少动态效果设置下立即展示全部内容。
- `frontend/demo-assets-plugin.ts`：仅本地开发使用的固定素材清单。

首页操作不请求生成 API、不创建任务、不调用模型、不扣额度。原图比较采用普通图片和浏览器裁剪，方法图是静态资源，滚动没有绑定重型动画循环。

沿用产品的 SVG 内容清理，并修复两个真实兼容问题：允许保留经过引用检查的 `<use>` 图形；使用 XML 序列化保存已清理的 DOM，避免 HTML `&nbsp;` 实体破坏 SVG XML。脚本、事件处理器、外部引用与禁止元素继续移除。拖动坐标使用父级变换矩阵，不按屏幕像素直接写入 SVG；点击不会立即捕获指针，从而保留双击编辑。

完整工作台、登录、草稿与编辑器未在此轮重写。当前应用仍把较多产品代码放在一个入口文件中；正式发布的性能整理应优先拆开公开页面与产品路由的加载，并进一步减少旧全局样式干扰。只因新增静态首页而更换整个框架没有必要。

下面是结合当前数据规模作出的设计判断，并非这些库对 FigFox 的实测结论：

1. 当前首选原图与重建结果的直接比较，同时让访问者编辑真实文字和图形。
2. 有统一指标后，用逐样本的前后配对点图，让改善、退步与个别异常可见，避免只有一个平均分。
3. 有完整成本口径后，增加质量与时间/费用散点；各点可关联输入与结果，并保留失败样本。
4. 方法对比必须共用数据集、版本、重试和人工介入口径；不能把历史恢复样本的数字当作正式排名。

DrawAI 的复杂评测图依赖其大量数据与指标。FigFox 目前应先展示可验证的成果，再添加与实际证据规模相称的图表。

## 同日布局与动效修订

用户指出首版把标题、画布和案例切换挤在一起，且没有感受到滚动衔接。这是首版视觉判断的不足：原先整块内容以 350 ms 提前进入，访问者滚动到主体时动画常已结束。

修订后，首屏只保留产品介绍、查看案例和 GitHub 入口，画布从下一部分开始。案例、原图对照与方法章节的标题统一居中，说明与图之间留出更明确的间距。手机和窄屏英文按钮分别核对，避免为留白牺牲完整内容。

进入效果改为分别观察标题、图和说明，650–700 ms 完成，展示块错开 90–150 ms。标题的位移为 24 px；SVG 画布只渐显。交互回归发现整体位移动画会影响刚进入画布时的拖动坐标，因此去掉了画布位移，并在获得焦点时立即结束其渐显。

浏览器逐帧检查记录了案例标题从透明度 0、位移 24 px 到透明度 1、位移 0 的过程，确认动效实际执行；减少动态效果设置下全部内容立即可见。布局截图覆盖 1440×960、2048×1116、1280×720、390×844、320×720 与 768×1024，中英文首屏介绍和入口完整，画布均从下一部分开始。中英文七种宽度的 14 个质量检查组合与 18 项案例交互回归通过。

修订截图、逐帧报告与实际浏览器滚动动图保存于 `frontend/.review/demo/layout-v2/`，便于直接核对空间和滚动效果。

## 同日首屏文字设计修订

用户进一步明确，此轮集中设计首屏的大标题和说明文字，并保留已经认可的留白。首屏继续使用居中的两行标题，第一行以较轻的字重和稍小的字号引出科研图像；第二行突出重建结果。英文 SVG 单独调整字号与字距，协调中英文的视觉大小。紫色到蓝色的静态渐变仅用于「可编辑 SVG」，没有增加新的展示图或装饰边框。

说明文字改为两层：「重建图中的文字、图形与连接关系。」与「继续编辑、调整布局，导出 SVG。」前者解释重建内容，后者说明后续操作；通过字号、字重和灰度区分。英文相应缩短，并对窄屏断行进行平衡，避免短词单独落在最后一行。第二层文字与背景的计算对比度为 4.78:1。

标题两行、说明和按钮在首次进入时依次轻微上移并渐显，每层持续 750 ms，最多延迟 300 ms；动画随后停止。减少动态效果设置下立即显示内容；系统高对比度模式下，渐变文字改为系统文字色。原有滚动衔接继续保留。

此轮生产构建通过。中英文七种宽度的 14 个首页质量检查组合全部通过，无溢出或浏览器错误；另检查了九组桌面、笔记本、平板与手机截图，首屏入口完整，案例画布仍从下一部分开始。浏览器采样记录了入场动画的中间透明度，并确认减少动态效果和系统高对比度模式下标题可见。截图和报告保存于 `frontend/.review/demo/hero-v3/`。

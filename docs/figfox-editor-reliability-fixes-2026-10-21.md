# 编辑操作与保存可靠性修复

本轮处理复查报告的 F1–F6，以及插入 SVG 未居中的问题。按用户要求，F7/F8 的虚线、粗体等 UI 状态反馈，以及字体、预设、质量选项等 UI 补齐留到下一轮。本轮不以这些修复宣称 SVG-Edit 已完整吸收。

## 改动

| 问题 | 修复与验证 |
| --- | --- |
| F1 相对单位导致导出固有尺寸变化 | 原生 em/ex 作为编辑显示偏好；独立 SVG 的画布宽高使用实际像素值，避免依赖外部查看器字体。mm 等物理单位保留。em/ex/mm 均完成修改→导出→关闭→重新打开，保持 800×600 与修改内容。FigFox 页面面板与文件采用一致的尺寸单位。 |
| F2 插入星形参数丢失 | 在引擎共同导入边界保留安全的展示/形状属性，再进行 ID 重映射。整份打开、插入、原生源代码路径共用处理；不再依赖导入后的旧 ID 查找。实测同名 ID 不影响原对象，星形比例 4、角数修改及上下标属性在保存重开后保留。 |
| F3 画布没有取得键盘焦点 | 选择模式点击画布时恢复 iframe 焦点，离开之前的输入框。文字编辑继续使用原生文字焦点逻辑。实测从外层缩放框回到画布即可使用方向键。 |
| F4 旋转组内键盘微调方向错误 | 鼠标拖动和键盘微调共用父坐标逆变换处理。25%/100% 缩放、旋转加非均匀缩放父组、Shift 步长、网格步长、撤销/重做均有针对性检查；属性输入框内方向键不会移动画布对象。 |
| F5 缩放按钮方向反转 | 数字输入和加减按钮统一为 1–6400%。检查 1000→1200、5→4 及两端限位。 |
| F6 线宽输入与文档不一致 | 线宽上限对齐原生 99，Enter 完成输入并显示实际限位值。检查 90、超限到 99、0，以及保存重开。未改变控件布局。 |
| 插入 SVG 没有居中 | 等待新 use 的引用树可测量后，按画布坐标居中；保留当时选区，定位属于原导入步骤。普通/原尺寸插入都居中，一次撤销/重做处理一次完整插入。 |

## 验证

开发页面上通过：

- `review:editor-reliability`：7 组针对性检查，覆盖上表的场景组合。输入、修改及重开 SVG 副本和结果保存在 `frontend/.review/editor-reliability/`。
- `review:editor-selection`：11 项原有选择、细小文字命中、拖动和文字编辑检查。
- `review:editor-capabilities`：15 项几何、结构化文字、渐变、图层及原生导出检查。
- `review:editor-parity`：10 项参数形状、标记、插入、原生入口及文件格式检查。
- `review:editor-save`：3 项导出、刷新恢复和保存失败处理检查。

上述合计为 46 个检查记录，不代表 46 个功能或整个编辑器全部验收。新检查同时记录引擎桥接错误，不能仅凭浏览器没有未捕获异常判断成功。

正式研究样本 D13/D14/D16 仍未在本轮验收。复杂文件性能热点仍需结合实际文件定位；本轮没有开展无针对性的压力测试，也未将性能风险记为已解决。

生产构建、公开同步和线上结果记录保存在本地 `frontend/.review/releases/2026-10-21-editor-reliability/`，发布镜像的 `_release.json` 记录实际源提交。
